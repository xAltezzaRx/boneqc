# BoneQC — руководство пользователя

## 1. Назначение

Этот документ описывает пользовательский workflow web-продукта BoneQC.

Competition evaluator описан отдельно в:

[competition/JUDGE_QUICKSTART.md](competition/JUDGE_QUICKSTART.md)

## 2. Основные роли

```text
ADMIN
OPERATOR
DOCTOR
```

### ADMIN

Управляет пользователями и административными функциями.

### OPERATOR

Работает с исследованиями и запускает автоматический QC.

### DOCTOR

Выполняет независимую экспертную оценку.

## 3. Типовой сценарий оператора

```text
Войти в систему
→ создать/открыть исследование
→ загрузить DICOM
→ дождаться проверки и подготовки
→ запустить анализ
→ дождаться AnalysisJob
→ открыть AnalysisResult
```

## 4. Результат QC

Основной результат:

```text
quality_class = 0 → PASS
quality_class = 1 → FAIL
```

Дополнительные поля:

```text
anatomical_region
violation_type
quality_prob
processing_status
```

## 5. Как читать PASS

PASS означает, что frozen C7 не выявил поддерживаемого нарушения технического качества.

PASS не означает отсутствие заболевания и не заменяет медицинское заключение.

## 6. Как читать FAIL

FAIL означает, что C7 выявил одно или несколько поддерживаемых технических нарушений.

Типы нарушений отображаются через `violation_type`.

## 7. Processing failure

Если файл невозможно корректно обработать, это не является PASS.

Техническая ошибка должна быть показана отдельно.

## 8. quality_prob

`quality_prob` — непрерывный QC score.

Не следует интерпретировать его как:

- accuracy;
- вероятность диагноза;
- вероятность того, что модель права;
- процент качества.

## 9. Expert review

DOCTOR может выполнить независимую оценку.

Blind workflow:

```text
открыть исследование
→ выполнить собственную оценку
→ сохранить annotation
→ после blind step увидеть automatic C7 result
```

## 10. Preview

Preview используется только для интерфейса.

Preview не является входом frozen C7.

## 11. Безопасность

Пользователь должен работать только с исследованиями, к которым у него есть разрешённый доступ.

Нельзя:

- публиковать medical DICOM;
- переносить real patient data в публичный repository;
- отправлять DICOM во внешние AI API без разрешённого контура.

## 12. Ограничения

BoneQC:

- поддерживает только заявленные anatomical regions;
- выполняет technical QC;
- не диагностирует остеопороз;
- не является зарегистрированным медицинским изделием.

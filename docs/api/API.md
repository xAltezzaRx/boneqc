# API BoneQC

## Назначение

Backend BoneQC реализован на FastAPI и обслуживает продуктовый веб-интерфейс, обработку исследований, экспертную разметку и административные функции.

## Версионирование

Основной API использует пространство `/api/v1`.

## Роли

Основные роли:

~~~text
ADMIN
OPERATOR
DOCTOR
~~~

### ADMIN

Администрирование системы и пользователей.

### OPERATOR

Работа с исследованиями и запуск автоматического анализа в рамках разрешённого доступа.

### DOCTOR

Независимая экспертная оценка исследований.

## Основные группы API

API включает функциональность для:

- health/readiness;
- authentication;
- studies;
- analysis jobs;
- results;
- expert annotations;
- dataset snapshots;
- models;
- operations;
- audit.

## Жизненный цикл исследования

~~~text
создание исследования
→ загрузка DICOM
→ подготовка данных
→ запуск анализа
→ AnalysisJob
→ AnalysisResult
~~~

## Асинхронный анализ

ML inference выполняется через worker.

HTTP-запрос не должен оставаться открытым на всё время обработки. Клиент получает идентификатор задания и отдельно запрашивает его состояние.

## Результат анализа

Основные поля:

~~~text
anatomical_region
quality_class
quality_prob
violation_type
processing_status
~~~

### quality_class

~~~text
0 → PASS
1 → FAIL
~~~

### quality_prob

Непрерывный QC score frozen C7.

Он не является accuracy модели или заявленной клинически откалиброванной вероятностью.

### violation_type

Содержит выявленный тип или типы нарушений качества.

### processing_status

Отражает технический статус обработки.

Неподдерживаемая анатомическая область не должна автоматически интерпретироваться как PASS.

## Экспертные аннотации

Экспертный API хранит независимую оценку врача отдельно от автоматического C7 result.

Поддерживаются:

- categorical labels;
- комментарии;
- geometry annotations;
- статус невозможности оценки.

## Audit

Критичные пользовательские и системные действия отражаются в audit trail.

## Security boundary

API должен обеспечивать:

- аутентификацию;
- RBAC;
- проверку доступа к исследованиям;
- безопасную работу с DICOM;
- разделение автоматического и экспертного контуров.

## Clinical boundary

API предоставляет результат технического QC.

Результат BoneQC не должен представляться как медицинский диагноз.
